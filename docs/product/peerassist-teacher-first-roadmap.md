# PeerAssist 教师优先产品路线图

**生效日期：** 2026-07-19

本路线图替代“先完成平台权限，再迁移 Next.js，再做核心体验”的产品排期。已有平台能力继续作为底座维护，但近期开发资源集中在老师可感知的完整审稿闭环。

## P0：先让一篇论文从头到尾可用

目标是消除当前截图中出现的假状态：失效 PDF 仍显示审稿中、数据库没有论文却显示旧摘要、任务失败后只能不断重试。

交付范围：

1. 首页直接上传 PDF，并展示最近论文。
2. 上传后可靠持久化论文，创建审稿任务并自动进入工作台。
3. PDF、摘要、任务状态和审稿产物使用同一个论文上下文，刷新后仍能恢复。
4. 资源不存在时自动清理失效缓存，回到可行动的空状态。
5. 任务状态统一为上传中、解析中、生成意见、待老师确认、已完成、失败；每个状态都有下一步操作。
6. 生成论文概要、重点阅读路线和结构化审稿初稿。
7. 支持编辑、删除、补充、复制和至少一种文件导出。
8. PDF 默认本地解析；外部模型按当前论文版本和审稿任务明确授权，拒绝后仍可继续本地阅读与编辑。
9. 服务端审稿文档支持自动保存和版本冲突提示；导出物成功生成并登记后才显示任务完成。

完成条件：使用 5 篇不同长度的真实可公开 PDF 连续验收，均能完成“登录 - 上传 - 阅读 - 查看摘要 - 编辑意见 - 导出”；页面刷新后上下文不丢失；不存在 404 PDF、永久加载、空白摘要或“有任务 ID 就显示运行中”的假状态。

## P1：让审稿结果值得老师使用

目标是从“能生成文字”提升到“能节省审稿时间”。

交付范围：

1. 每条主要意见绑定页码、原文片段和影响说明。
2. 提供总体评价、主要问题、次要问题和修改建议四段式编辑器。
3. 提供快速审稿与完整审稿两种清晰模式，不暴露底层 Agent 编排。
4. 提供课程论文、学位论文、期刊审稿三类模板。
5. 失败任务支持重试，模型不可用时明确说明哪些结果未生成。
6. 邀请 3 至 5 名老师完成真实任务访谈和可用性测试。

完成条件：至少 80% 的试用老师无需讲解完成主流程；AI 意见经接受或改写后的保留率达到 50%；老师能解释系统当前状态和下一步动作。

## P2：让老师愿意持续使用

目标是形成稳定复用，而不是一次性演示。

交付范围包括历史论文搜索、审稿模板复用、批量上传、常用意见库、导出格式定制、费用与耗时提示，以及老师明确提出的团队协作需求。OJS/OpenReview 等系统优先通过复制、文件导出或轻量连接器集成，不在 PeerAssist 内重建投稿和分稿流程。是否迁移 Next.js、是否增加证据画布、是否扩展成员角色，都由 P0/P1 的实际数据和访谈决定。

完成条件：试用老师在四周内重复使用；历史任务能够快速找回；导出结果能直接进入现有教学或同行评审流程。

## P3：平台化与规模化

只有当真实团队协作、院系部署或 SaaS 需求出现后，再集中建设多组织、多角色、审计、配额、分享治理、完整 Next.js 迁移和大规模恢复测试。届时复用现有 FastAPI、PostgreSQL、OIDC 和 S3 能力，不要求老师感知这些技术组件。

## 当前两周优先级

1. 修复失效论文缓存、PDF 404、摘要假加载和任务假运行状态。
2. 打通真实 PDF 上传到摘要与审稿初稿生成。
3. 将教师导航统一为“我的审稿、论文研读、审稿意见、历史记录”，隐藏非核心技术入口。
4. 在 Worker 外部调用前校验逐任务模型授权，拒绝或模型不可用时提供明确的本地降级。
5. 将审稿草稿升级为服务端权威文档，显示保存失败和版本冲突。
6. 完成意见编辑与复制/导出，并确保导出成功后再标记完成。
7. 最后集中验证登录、模型配置、普通老师使用和管理员运维。

本阶段不继续扩展 RBAC、租户矩阵、无限画布和大范围 Next.js 迁移。
