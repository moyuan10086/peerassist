# PeerAssist 纸页研读室 UI 设计

日期：2026-07-14

## 1. 目标

将 PeerAssist 审稿工作区改造成“纸页研读室”：以大尺寸、可选择文字的 PDF 为第一视觉层级，以可收起审稿抽屉承载待确认意见、引用核查和专业代理结果。视觉应温和、安静、适合长时间阅读，同时保留清晰的任务状态和高效操作，不把学术审稿包装成等级、积分或娱乐任务。

已确认的视觉方向：

- 风格 A：安静纸感。
- 布局 A2：PDF 近全宽，可收起审稿抽屉。

## 2. 信息架构

桌面工作区由四层组成：

1. 顶部细导航：论文标题、任务状态、页码与关键命令。
2. 左侧窄导航：论文、审稿、引用、专业审阅、报告。
3. 中央阅读面：PDF、文字层、证据高亮和页边批注标记。
4. 右侧审稿书签/抽屉：默认收起，仅显示待确认数量和当前页标记；展开后显示结构化审稿内容。

PDF 始终是最大的区域。抽屉收起时不得保留空白栏或压缩页面；抽屉展开时宽度受 `min/max` 约束，并保持到用户主动关闭。阅读面和抽屉之间不使用嵌套卡片。

## 3. 审稿抽屉

### 3.1 打开方式

以下操作自动展开抽屉并定位对应内容：

- 点击 PDF 页边 concern 标记。
- 点击引用高亮或引用标记。
- 文字选择后发起人工批注。
- 从审稿进度、专业审阅或报告回到原文证据。

用户可通过书签按钮或关闭按钮手动收起。抽屉一旦打开，在翻页、切换单双页和切换标签时保持展开，直到用户主动关闭；不提供含义模糊的“固定”状态。收起/展开偏好存入浏览器本地，但任务数据和未提交批注不依赖该偏好。

### 3.2 标签

抽屉使用四个标签：

- `待确认`：当前页优先，然后显示全篇 pending concerns。
- `引用核查`：当前页 mention 优先，展示参考文献、外部核验和人工结论。
- `专业审阅`：结构、方法、实验、统计、引用、伦理与复现代理状态和发现。
- `人工批注`：显示当前文字选区、页码、原文片段、批注编辑框和提交/清除操作；保留现有人工审稿助手的功能，不把未提交内容混入自动 concern。

抽屉打开时，页边标记、PDF 高亮、抽屉条目和 concern ID 必须保持同一选中状态。

## 4. PDF 阅读面

- 保留单页/双页、缩放、适合宽度、页码输入和文字选择。
- 收起抽屉后重新计算可用宽度，但不得重置当前页、缩放偏好、已快照的文字选区草稿或证据高亮。
- 文字选择触发抽屉时，必须在改变布局前同步保存 `selectedText`、页码、source text layer 和可恢复的范围信息；抽屉展开导致 text layer 重建时，浏览器原生选区可以消失，但“人工批注”中的选区草稿和页面证据不得丢失。
- 用户仍按住鼠标或触摸选择手柄时不得启动宽度过渡；必须等 `mouseup`/selection snapshot 完成后再展开。
- 双页模式继续采用封面单页、后续 `2-3`、`4-5` 配对。
- 页边标记保持固定点击尺寸，多个相近标记继续进行垂直避让。
- 纸张纹理只能使用极低对比度 CSS 噪声或纯色，不得覆盖 canvas/text layer，不得降低文字选择和 bbox 对齐精度。
- PDF 加载、文字层和证据层分别显示状态，动态内容不得改变工具栏尺寸。

## 5. 视觉语言

### 5.1 色彩

主色不是单一米色：

- 稿纸：暖白 `#fffdf8`。
- 页面背景：灰绿 `#e7ebe7`。
- 导航墨绿：`#35594c`。
- 批注朱红：`#c95f4d`。
- 证据淡黄：`#f2d98d`。
- 引用蓝：`#4f7f9c`。
- 正文墨色：`#2f3934`。

颜色必须通过状态文字或图标补充含义，不能单独表达成功、警告和失败。

### 5.2 形状与层次

- 页面、工具栏和抽屉使用 0-6px 圆角；不使用大胶囊和漂浮卡片墙。
- PDF 保持真实纸页阴影，其他区域使用边框和色带建立层次。
- concern 使用便笺式左侧色条，不放在另一张装饰卡片内部。
- 图标优先使用现有 Lucide 图标；熟悉操作不使用文字胶囊代替图标。
- 动效只用于抽屉、选中状态和证据定位，时长 120-220ms，并支持 `prefers-reduced-motion`。

### 5.3 字体

- UI 正文沿用可靠中文无衬线字体。
- 论文标题、抽屉标题可使用系统可用的中文衬线字体栈，失败时稳定回退。
- 不从公网加载字体，不增加首屏外部依赖。
- 字号不随 viewport 宽度连续缩放；紧凑面板标题不使用 hero 字号。

## 6. 中文文案

面向审稿人的文本使用动作和结果，不暴露内部实现术语：

| 现有或内部表达 | 新界面表达 |
|---|---|
| 多代理结果 | 专业审阅 |
| candidate concern | 待确认意见 |
| concern | 审稿意见 / 关注点 |
| agent run | 专业审阅进度 |
| 模型未启用 | 当前使用本地证据规则 |
| local fallback | 已切换为本地核查 |
| model enhanced | 已完成模型辅助审阅 |
| evidence count | 已定位证据 |
| finding count | 发现关注点 |
| awaiting human confirmation | 等待逐条确认 |
| finalize | 生成审稿报告 |

状态文案示例：

- 解析：`正在整理原文与版面`。
- 画像：`正在提取研究问题、方法和实验`。
- 引用：`正在核对正文引用与参考文献`。
- 代理：`正在进行结构、方法和实验审阅`。
- 降级：`外部模型未配置，本轮使用本地证据规则继续审阅`。

不在界面中使用“Level”“任务经验”“通关”“奖励”等游戏化词汇。

## 7. 响应式行为

### 7.1 宽桌面

- 抽屉收起为 52-72px 书签栏。
- 展开宽度默认 360px，允许在 320-480px 内调整。
- PDF 阅读区占剩余宽度。

### 7.2 窄桌面/平板

- 左侧导航收为图标栏。
- 抽屉以覆盖层方式从右侧出现，不重新排版 PDF canvas。
- 抽屉外区域可点击关闭。

### 7.3 手机

- PDF 强制单页全宽。
- 左侧导航变为底部导航。
- 审稿抽屉变为底部面板，默认显示标题和数量，展开后占视口 55-85%。
- 面板必须避开浏览器安全区域，正文和按钮不得横向溢出。

## 8. 状态与错误

- PDF 尚未可读时，阅读面显示明确解析/加载状态；不能用空白 canvas 冒充加载成功。
- 文字层未完成时禁用“选择文字批注”，但缩放与翻页可继续。
- concern 无 bbox 时仍可按 page/locator 跳转，并在抽屉说明“已定位到页面，精确位置待核对”。
- 后台失败、取消和重试状态继续从持久事件恢复，刷新后抽屉状态与任务事实分离。
- 外部模型/OCR/检索未授权时，使用中性解释并显示本地路径，不显示错误式红色警报。

## 9. 性能约束

- 不引入 Three.js；PDF 是文档阅读，不需要 3D 渲染。
- 不增加阻塞首屏的大图、远程字体或全屏纹理资产。
- PDF worker、canvas 和 text layer 生命周期不因抽屉开关而重新创建文档实例。
- 抽屉内容按当前标签渲染，长列表使用现有分页/限制或虚拟化策略。
- 保持现有 Range 请求和 PDF.js worker 缓存路径。

## 10. 验收

浏览器验收至少覆盖：

- 1440x960：抽屉收起时 PDF 明显扩大；展开后可完成 concern 确认和引用查看。
- 1600x1000 双页：页边标记、右页证据和抽屉条目保持双向定位。
- 390x844：单页 PDF、底部审稿面板、无水平溢出和遮挡。
- 文字选择快照、批注草稿、缩放、翻页和单双页切换不因抽屉开关丢失状态。
- 选区触发抽屉后即使 text layer 因 ResizeObserver 重建，人工批注标签仍保留原文、页码和未提交文本。
- 刷新恢复 ReviewJob、当前论文、待确认数量和持久时间线。
- canvas 像素检查非空，text layer 可选择，控制台无错误。
- 中文文案不再暴露 `candidate concern`、`agent run`、`local fallback` 等内部表达。

## 11. 非目标

- 不把 PeerAssist 改成营销首页或游戏。
- 不重写 PDF.js 核心渲染器。
- 不以装饰牺牲信息密度、可访问性或学术严肃性。
- 不在本轮改变后端 concern、confirmation 或 report 的权威数据契约。
