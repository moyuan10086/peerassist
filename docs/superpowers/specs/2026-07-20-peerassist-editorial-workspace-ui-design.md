# PeerAssist 学术编辑工作台 UI 设计

**状态：** 已确认，进入实现
**日期：** 2026-07-20

## 目标

让老师在一个连续工作流中完成：上传论文、快速理解、定位证据、修改意见和导出结果。界面不把 Review Job、Agent、EventSource 等实现概念放在主路径上。

## 第一性原理

- 用户的产出是可交付的审稿意见，不是运行一个 Agent。
- 每个页面状态都必须回答“发生了什么”和“下一步做什么”。
- 论文上下文必须持续可见，刷新和返回不能让用户重新寻找当前稿件。
- AI 结论只有在证据可定位、状态可解释、可被编辑时才值得信任。
- 主界面只保留一个主动作，管理、模型和运行细节进入次级入口。

## 视觉方向

采用“学术编辑工作台”方向：纸张白、墨黑、暗青绿和琥珀提示色；标题使用本地可用的学术衬线字体栈，正文使用高可读无衬线字体；降低阴影、圆角和卡片嵌套，使用边界线和留白建立层级。

## 布局与交互

- 桌面端使用 220px 导航、主阅读区、360px 证据栏三段布局。
- 顶部仅显示产品标识、当前论文/任务状态、一个主动作和账号入口。
- 导航分为“阅读”“审稿”“证据”“交付”，技术追踪与管理入口收进更多菜单。
- 论文页优先展示标题、摘要结论、PDF 阅读和当前证据；加载、失败和完成状态都带有下一步动作。
- 审稿草稿使用编辑器，支持保留原文、修改、复制和 Markdown 导出。
- 移动端折叠导航和证据栏，阅读区保持单列，触控目标不小于 44px。

## 验收

- 主视图不出现 Review Job、EventSource、Agent 等内部术语。
- 当前论文标题和任务状态在阅读与审稿页面持续可见。
- 关键状态包含可执行主按钮，不能只显示 spinner 或空白灰区。
- 375px、768px、1440px 宽度下无横向溢出，焦点环和键盘顺序可用。
- 前端构建通过，现有论文/上传/审稿行为不改变。
