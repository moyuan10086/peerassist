# PeerAssist 学术编辑工作台 UI 设计

**状态：** 部分被 2026-07-24 证据驱动审稿工作台规格覆盖
**日期：** 2026-07-20

本文件保留视觉方向、响应式布局、PDF 画布、选区快照、焦点管理和证据定位约定。教师端导航以“我的审稿、论文研读、审稿意见、历史记录”为准；草稿以服务端 `ReviewDocument` 为权威，不再以浏览器本地草稿为恢复基线；具体覆盖关系见 `2026-07-24-peerassist-evidence-review-workspace-positioning-design.md`。

根目录 `DESIGN.md` 是 PeerAssist 视觉 token、组件样式约束与无障碍对比度要求的规范性来源，所有前端实现和设计评审必须以其为准。

## 目标

让老师在一个连续工作流中完成：上传论文、快速理解、定位证据、修改意见和导出结果。界面不把 Review Job、Agent、EventSource 等实现概念放在主路径上。

## 第一性原理

- 用户的产出是可交付的审稿意见，不是运行一个 Agent。
- 每个页面状态都必须回答“发生了什么”和“下一步做什么”。
- 论文上下文必须持续可见，刷新和返回不能让用户重新寻找当前稿件。
- AI 结论只有在证据可定位、状态可解释、可被编辑时才值得信任。
- 主界面只保留一个主动作，管理、模型和运行细节进入次级入口。

## 数据与权限边界

- 论文和 PDF 仍由 `Paper`/`PaperVersion` API 与 MinIO 持有，阅读页只读取当前用户所属项目的数据。
- 任务状态和摘要/报告由 `ReviewJob`、`Artifact` 和事件 API 负责；UI 不根据本地状态伪造完成结果。
- 逐条意见继续通过候选 finding、人工决策事件和导出冻结修改；`ReviewDocument` 是可编辑正文的服务端权威值，不改变历史 AI Artifact。
- 复制和文件下载是用户主动操作；最终导出冻结文档、决策事件和 finding revision。未登录、无项目成员权限或稿件不存在时不渲染内容。
- 浏览器可保存尚未提交的短期编辑缓冲，但刷新恢复以服务端 `ReviewDocument` 为基线；版本冲突必须可见，退出登录或稿件失效时清理本地缓冲。

## 视觉方向

采用“学术编辑工作台”方向：纸张白、墨黑、暗青绿和琥珀提示色；标题使用本地可用的学术衬线字体栈，正文使用高可读无衬线字体；降低阴影、圆角和卡片嵌套，使用边界线和留白建立层级。

## 布局与交互

- 桌面端使用 220px 导航、主阅读区、360px 证据栏三段布局。
- 顶部仅显示产品标识、当前论文/任务状态、一个主动作和账号入口。
- 导航分为“我的审稿”“论文研读”“审稿意见”“历史记录”，技术追踪从普通老师导航移除，管理入口只对管理员显示。
- 论文页优先展示标题、摘要结论、PDF 阅读和当前证据；加载、失败和完成状态都带有下一步动作。
- 审稿草稿使用编辑器，支持保留原文、修改、复制和 Markdown 导出。
- 移动端折叠导航和证据栏，阅读区保持单列，触控目标不小于 44px。

断点明确为：`>= 1180px` 三段布局；`768px-1179px` 导航收窄为 72px、证据栏变为可展开覆盖层；`<768px` 导航变为底部栏、证据栏变为全宽抽屉。PDF 阅读区在平板和移动端至少保留 280px 高度，不允许三栏同时挤压主内容。

## 状态与动作

| 状态 | 主视图文案 | 唯一主动作 |
| --- | --- | --- |
| 无论文 | 还没有打开论文 | 上传论文 |
| 上传/解析中 | 正在准备论文，并显示阶段 | 查看任务 |
| 排队/运行中 | 正在排队或生成摘要/意见 | 查看进度；次要操作为取消 |
| 需要授权 | 需要老师允许模型或外部服务 | 授权并继续；次要操作为取消 |
| 待确认 | 结果已生成，等待老师判断 | 打开证据队列；次要操作为取消 |
| 取消请求中 | 正在停止当前任务 | 等待停止，不重复提交 |
| 已取消 | 任务已停止，原始论文保留 | 重试 |
| 已完成 | 导出文件已生成并登记 | 打开最终报告；继续编辑会创建新的文档版本 |
| 失败/中断 | 说明安全错误和恢复点 | 重试 |
| 无权限/过期 | 论文内容已锁定 | 返回项目或登录 |

摘要缺失时显示“尚未生成”和查看原文入口；证据缺失或定位不精确时标记“待人工核查”，不显示确定性结论。选区、finding lineage 和 PDF 页码通过聚合 API 保持同步。

宽屏证据栏默认打开，用户可以通过顶部图标收起；平板证据栏默认收起，点击“查看证据”以覆盖层打开；移动端从底部抽屉打开。关闭时将焦点还给触发按钮，打开时将焦点移到标题，遮罩层和 Escape 键均可关闭，背景内容保持 inert。当前选中的 finding lineage 和 PDF 页码保存在页面状态，刷新后由聚合 API 恢复。

## 验收

- 主视图不出现 Review Job、EventSource、Agent 等内部术语。
- 当前论文标题和任务状态在阅读与审稿页面持续可见。
- 关键状态包含可执行主按钮，不能只显示 spinner 或空白灰区。
- 375px、768px、1440px 宽度下无横向溢出，焦点环、键盘顺序、`aria-live` 状态播报和 `prefers-reduced-motion` 可用。
- 前端构建通过，现有论文/上传/审稿行为不改变。

## 本轮范围与回归场景

当前实现范围包括四入口信息架构、视觉 tokens、响应式布局、平台模型授权、服务端 `ReviewDocument`、finding 决策、导出完成语义和失败恢复；不扩展复杂权限、Agent 编排或多人实时协作。用户路径回归覆盖四个教师入口、管理员设置和登录，契约回归覆盖模型授权、取消、重试、finding 决策、文档冲突、导出部分失败和未登录/无权限访问；`/agent`、`/queue`、`/trace`、`/artifacts` 仅作为隐藏诊断兼容路由验证。
