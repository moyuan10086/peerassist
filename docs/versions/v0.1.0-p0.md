# PeerAssist `0.1.0-p0` 版本说明

## 定位

PeerAssist 是面向高校教师和科研人员的证据驱动 AI 审稿工作台：上传论文，阅读原文，生成带证据定位的审稿关注点，人工确认后导出报告。

## 当前能力

- 任务级 `ExternalServiceConsent`，模型外调前校验 provider、授权和数据范围。
- `ReviewDocument` 四段式服务端文档，finding 与 evidence 强绑定，支持 CAS 和人工决策投影。
- 教师工作台 API：上传论文、创建任务、读取/编辑文档、证据和 finding 决策、异步导出。
- 旧文件型任务通过唯一 registration/迁移适配层接入；未授权或 provider 不可用时阻断，不静默外传。
- `ReportVersion + Artifact` 记录不可变报告；导出失败可重试，兼容旧 `/finalize` 入口。
- 前端包含登录入口、论文阅读、智能审稿、证据队列、人工确认、产物导出和管理员设置。

## 与旧版本的架构差异

| 维度 | 旧 `peerassist-mvp` | 当前 `0.1.0-p0` |
| --- | --- | --- |
| 运行入口 | 单体确认页/本地文件工作区 | 8766 教师工作台 + 8767 durable Review Job API + 平台 API |
| 数据权威 | `runs` 目录中的 JSON/Markdown | PostgreSQL 领域数据、MinIO 对象、worker scratch；legacy 只读 |
| 身份 | 无稳定平台会话或依赖外部入口 | Keycloak OIDC、PKCE、服务端会话、CSRF、同源 `/identity` 网关 |
| 租户边界 | 以 paper/run 路径区分 | organization/project/member/role 作用域与服务端授权 |
| 审稿状态 | 页面读取运行态快照 | ReviewJob、attempt、stage manifest、outbox、事件时间线 |
| 证据与意见 | 队列项和本地草稿为主 | ReviewDocument、finding/evidence 绑定、版本/CAS、人工决策投影 |
| 外部模型 | 全局配置后直接调用 | 任务级同意 + provider/policy/data-scope 门禁；失败可降级 |
| 导出 | HTTP 请求内生成结果 | 冻结快照后异步导出，登记 ReportVersion/Artifact，失败可重试 |
| 前端 | 单页面确认控制台 | 可复用的 React/Vite 工作台，登录后按项目进入论文审阅闭环 |

## 复用与迁移

当前版本没有复制旧系统。旧系统可复用的部分保留在：

- `src/peerassist/confirmation_server.py`：兼容 HTTP 路由、PDF/事件读取和 legacy 代理。
- `src/peerassist/review_job_api.py`：旧任务 API 的兼容入口。
- `src/peerassist/platform/adapters/legacy.py`：将旧 run 事实登记为只读 legacy registration。
- `src/peerassist/review_context.py`、`src/peerassist/confirmation_workflow.py`：复用解析、证据和确认逻辑。
- `web/peerassist-workspace/src/main.tsx`、`styles.css`：唯一前端源文件；新 UI 在此增量演进。

迁移顺序是“先登记、再冻结快照、再由新 worker 接管”；旧数据不被覆盖，未满足 provider/授权条件的任务保持 blocked 并要求重新授权。

## 部署基线

- 2026-07-25 发布时，8766/8767 systemd unit 的 `WorkingDirectory` 和 Python 路径指向旧 worktree；该路径只代表当时的部署事实，当前服务已迁移至 `/root/PeerAssist`。
- 8766 使用 `PEERASSIST_PLATFORM_API_URL=http://127.0.0.1:8000`，并通过 `PEERASSIST_IDENTITY_GATEWAY_URL` 代理同源 Keycloak `/identity`。
- 本机 systemd 的平台栈恢复单元会先恢复既有容器，再动态读取 Keycloak 容器 IP；不要把容器 IP 写死到仓库模板。
- PostgreSQL、MinIO、Keycloak 和平台 API 使用既有 Compose 项目与持久卷；宿主机重启后应恢复同一 Compose 项目，不得启动旧目录服务。
- 当前 readiness：database、identity、object_store 均为 `ready`。

## 版本边界

`0.1.0-p0` 是教师审稿闭环的第一个可部署基线。下一版本应继续增量修改当前模块并追加版本说明，不创建 `v2` 平行源码目录。
